## Lark API 教训：循环事件实例

**问题**：Lark Calendar API 的 `instances` 接口能列出循环事件的未来实例，但 DELETE 这些实例返回 "event not found"（404）。EXDATE 修改 recurrence rule 也返回 "invalid parameters"。

**解决方案**：UNTIL + 重建
1. PATCH 原循环事件加 `UNTIL=截止日期`（结束旧系列）
2. POST 创建新循环事件（从恢复日期开始）

**注意**：DELETE `event_id_0`（带 `_0` 后缀）会删除**整个循环系列**，不只是第一个实例！

## Lark API 确认（Carl 帮忙查文档）

DELETE /calendar/v4/calendars/{calendar_id}/events/{event_id} 文档确认：
- **无任何循环实例相关参数**（无 delete_scope / this_event）
- event_id 来源只有：创建返回 / 事件列表 / 搜索——都不返回虚拟实例 ID
- `instances` API 返回的 `{base_id}_{timestamp}` ID 在 DELETE/GET/PATCH 上都是 404
- **结论：Lark 不支持删除循环事件的单个虚拟实例，UNTIL + 重建是正确 workaround**

## Lark 循环事件删除 — 最终结论（测试验证）

### 测试过程
创建临时循环事件，分别用 Events LIST 和 Instances API 尝试删除单个实例：

| 方法 | 返回的 ID | 能删除吗 |
|------|-----------|----------|
| Events LIST API | 永远只有 `_0` (master) | 删 = 删整个系列 ⚠️ |
| Instances API | `_{timestamp}` 格式 | ❌ 404 event not found |
| EXDATE 修改 recurrence | N/A | ❌ 190002 invalid params |

### 结论
- Gemini 说的"通过 LIST 拿实例 ID 再删"在 Lark 上不成立
- Events LIST **永远只返回 master `_0`**，不管查哪天
- **UNTIL + 重建是唯一方案**
- 已创建工具脚本: `scripts/skip-recurring-dates.py`
- 已修复日历显示脚本: `scripts/lark-calendar-today.py` (UNTIL 支持)
