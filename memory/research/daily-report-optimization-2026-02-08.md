> 目的：为 Luna 的日报生成功能提供更好的时间分析和复盘框架，使日报从"流水账"升级为"可执行洞察"

## 一、时间管理分析框架：从日历数据中提取洞察

### 1.1 时间分类体系

从日历事件中提取有意义的分析，首先需要建立统一的时间分类体系。推荐采用**四层分类法**：

| 层级 | 分类 | 示例 |
|------|------|------|
| L1 深度工作 | 需要高认知负荷、不可中断的工作 | 编码、写文档、战略思考、研究 |
| L2 协作工作 | 与他人交互但有产出的工作 | 1:1 会议、技术评审、头脑风暴 |
| L3 运营工作 | 必要但认知负荷低的工作 | 站会、状态同步、邮件处理、审批 |
| L4 非工作时间 | 休息和生活 | 午餐、通勤、休息 |

**实操建议：** Luna 可以根据日历事件的标题和描述自动分类。建议维护一个分类映射表（`time-categories.json`），将常见事件关键词映射到分类，例如：

```json
{
  "deep_work_keywords": ["coding", "编码", "写作", "research", "设计", "review PR"],
  "collab_keywords": ["1:1", "brainstorm", "评审", "讨论", "sync"],
  "ops_keywords": ["standup", "站会", "周会", "all-hands", "admin"],
  "break_keywords": ["lunch", "午餐", "break", "休息"]
}
```

### 1.2 核心生产力指标

以下是从日历数据中可以计算的关键指标，每个指标都附带计算方法和健康基准：

#### 1.2.1 深度工作时间（Deep Work Hours）

- **定义：** L1 类事件的总时长
- **计算：** `sum(L1 事件时长)`
- **健康基准：** Cal Newport 建议知识工作者每天 3-4 小时深度工作为佳，每周 15-20 小时
- **日报展示：** `深度工作：3.5h ▓▓▓▓▓▓▓░░░ (目标 4h)`

#### 1.2.2 时间碎片化指数（Fragmentation Index）

这是最被忽视但最有价值的指标之一。

- **定义：** 衡量工作时间被打断的程度
- **计算方法：**
  ```
  碎片化指数 = (上下文切换次数) / (工作总小时数)
  上下文切换 = 不同类型事件之间的切换次数
  ```
- **解释：**
  - < 2.0：低碎片化，专注度好
  - 2.0-4.0：中等碎片化，可以优化
  - > 4.0：高碎片化，生产力严重受损
- **日报展示：** `碎片化指数：2.8 (中等) ⚠️ 建议合并下午的零散会议`

#### 1.2.3 会议负荷率（Meeting Load）

- **定义：** 会议时间占工作总时间的比例
- **计算：** `(L2 + L3 中会议类事件时长) / 工作总时长 × 100%`
- **健康基准：**
  - IC（个人贡献者）：< 30% 理想，> 50% 危险
  - 管理者：< 50% 理想，> 70% 危险
- **日报展示：** `会议负荷：35% ▓▓▓▓▓▓▓░░░░░░░░░░░░░ (基准 30%)`

#### 1.2.4 最长连续专注时段（Longest Focus Block）

- **定义：** 一天中没有会议或切换的最长连续工作时间
- **计算：** 找到日历中两个会议之间的最大空隙
- **健康基准：** ≥ 2 小时才能进入真正的心流状态（进入心流需要 15-20 分钟热身）
- **日报展示：** `最长专注：2h15m (09:30-11:45) ✅`

#### 1.2.5 Maker-Manager 比率

源自 Paul Graham 的经典框架。

- **定义：** Maker 时间（≥2h 的连续无会议时段）与 Manager 时间（以会议为主的时段）的比率
- **计算：** `Maker 时段数 / 总可用半天数`
- **日报展示：** `Maker/Manager：3/2（上午 Maker，下午偏 Manager）`

### 1.3 趋势对比分析

单日指标价值有限，真正有用的是**趋势**。Luna 应该维护一个历史指标数据库（建议用 JSON 文件），存储每日的核心指标：

```json
// memory/metrics/daily-metrics.json
{
  "2026-02-07": {
    "deep_work_hours": 3.5,
    "fragmentation_index": 2.8,
    "meeting_load_pct": 35,
    "longest_focus_min": 135,
    "maker_blocks": 3,
    "total_work_hours": 9.5
  }
}
```

**趋势分析维度：**

1. **周环比：** 本周 vs 上周同一天，检测是否有恶化趋势
2. **滚动 7 天平均：** 平滑波动，发现真实趋势
3. **日内分布模式：** 将一天分为上午/下午/晚上，统计各时段的深度工作占比

**日报中的趋势展示：**
```
📊 本周趋势（vs 上周）
  深度工作：17.5h → 15.2h ↓13% ⚠️
  碎片化：2.1 → 2.8 ↑33% ⚠️
  最长专注：平均 2.5h → 1.8h ↓28% ⚠️
  💡 观察：本周会议增多，建议下周二/四设为「无会议日」
```

## 二、个人复盘框架

### 2.1 推荐框架：改良 KPT + LNO 混合框架

经过对多种复盘框架的对比分析，推荐将日本 Toyota 的 KPT 框架与 Shreyas Doshi 的 LNO 框架结合，创建一个适合个人日报的混合框架：

#### KPT 框架回顾

- **Keep（继续）：** 今天哪些做法效果好，应该保持？
- **Problem（问题）：** 遇到了什么阻碍或低效问题？
- **Try（尝试）：** 明天要尝试什么新做法来改善？

#### LNO 框架回顾

- **Leverage（杠杆）：** 哪些事产生了 10x 回报？投入是否足够？
- **Neutral（中性）：** 哪些事做到了"刚好够好"？
- **Overhead（开销）：** 哪些事是必要但低回报的？能否减少或自动化？

#### 混合框架：每日 KLPT 复盘

将两者融合为一个适合日报的精简框架：

```
## 📋 今日复盘

### 🎯 杠杆事项（Leverage）
- [完成的高价值工作] → 产出/影响
- [未完成但推进了的高价值工作] → 当前进度

### ✅ 继续保持（Keep）
- [有效的工作习惯/方法]

### ⚠️ 问题与阻碍（Problem）
- [遇到的障碍] → 根因分析

### 🔄 明日尝试（Try）
- [具体的改善行动] → 预期效果
```

结合以上所有框架，推荐的完整日报结构：

### 2.3 与 OKR 追踪结合

如果 Carl 设定了个人 OKR，日报应在每周末增加 OKR 进度追踪板块：

```markdown
## 🎯 OKR 进度（周视图）

### O1: [目标描述]
- KR1: [关键结果] — 进度 60% ▓▓▓▓▓▓░░░░ — 状态：🟢 On Track
- KR2: [关键结果] — 进度 30% ▓▓▓░░░░░░░ — 状态：🟡 At Risk
  - 本周动作：[具体做了什么]
  - 下周计划：[准备做什么]

### O2: [目标描述]
- KR1: [关键结果] — 进度 80% ▓▓▓▓▓▓▓▓░░ — 状态：🟢 On Track
```

**OKR 与日报的具体结合方法：**

1. **每日：** 在日报的「杠杆事项」中标注哪些工作直接推进了哪个 KR
2. **每周五/周日：** 自动计算 KR 进度，标注状态灯（绿/黄/红）
3. **月末：** 生成月度 OKR 回顾报告，包含完成率、偏差分析、下月调整

### 2.4 其他复盘框架参考

以下框架可以作为补充，在特定场景下使用：

| 框架 | 适用场景 | 核心问题 |
|------|----------|----------|
| **4Ls**（Liked, Learned, Lacked, Longed For） | 周复盘、感性回顾 | 带入情感维度，不仅看事实还看感受 |
| **Start-Stop-Continue** | 习惯调整 | 哪些新习惯要开始？哪些坏习惯要停止？哪些好习惯要继续？ |
| **SCRUM Standup** | 日常快速同步 | 昨天做了什么？今天要做什么？有什么阻碍？ |
| **5 Whys** | 深度问题分析 | 对某个问题连问5个"为什么"，找到根因 |
| **能量曲线** | 生物节律优化 | 记录每小时的主观能量水平，发现高效时段 |

建议 Luna 在日报中默认使用 KLPT 框架，在周报中使用 4Ls 框架增加感性维度。

## 三、数据驱动的改进建议

### 3.1 习惯模式识别

通过积累 2-4 周的历史数据，Luna 可以识别以下模式并在日报中提示：

#### 3.1.1 高效时段识别

```
分析方法：
1. 将每天分为 6 个时段（早/上午前半/上午后半/下午前半/下午后半/晚上）
2. 统计每个时段的深度工作完成率
3. 4 周后计算各时段的平均深度工作时长

输出示例：
💡 高效时段分析（过去4周）
  🟢 09:00-11:00 — 平均深度工作 1.6h/2h（80%利用率），这是你的黄金时段
  🟡 14:00-16:00 — 平均深度工作 0.8h/2h（40%），经常被会议打断
  🔴 16:00-18:00 — 平均深度工作 0.3h/2h（15%），多为运营工作
  
  建议：将高认知任务集中在 09:00-11:00，下午安排协作和运营工作
```

#### 3.1.2 会议模式分析

```
分析维度：
- 固定周期会议 vs 临时会议的比例
- 会议平均时长（是否有过度开会倾向）
- 会议间隔时间（是否有足够的切换缓冲）
- 「独角兽会议」：只有你一个人参加的外部会议，可能可以异步替代

输出示例：
📊 会议模式（本周）
  固定会议：6 场 (60%)，临时会议：4 场 (40%)
  平均时长：42min（基准 30min，偏长 ⚠️）
  平均间隔：18min（建议 ≥ 15min ✅）
  建议：周三的 XX 同步会可以改为异步文档更新
```

#### 3.1.3 工作节奏模式

```
分析维度：
- 每日开始/结束工作时间的规律性
- 是否存在"深夜加班"模式（>21:00 还有日历事件）
- 周末工作频率
- 连续工作天数（burnout 风险）

输出示例：
🔔 工作节奏提醒
  本周连续 6 天有工作安排（上周也是），建议安排完整休息日
  过去 2 周有 3 天工作到 22:00 后，注意睡眠质量
  起床时间稳定在 08:30±15min，节律健康 ✅
```

### 3.3 周报与月报的自动聚合

日报数据可以自动聚合为更高层级的报告：

**周报自动生成内容：**

## 四、实施路线图

### Phase 1：基础指标（立即可做）

1. 在日报生成脚本中增加时间分类逻辑
2. 计算 4 个核心指标（深度工作、碎片化、会议负荷、最长专注）
3. 用 ASCII 条形图可视化时间分配
4. 存储每日指标到 `memory/metrics/daily-metrics.json`

### Phase 2：复盘框架（1-2 天内）

1. 在日报模板中加入 KLPT 复盘板块
2. 根据日历事件自动生成「杠杆事项」提示
3. 从前一天日报中提取 Try 项目，在今天日报中追踪

### Phase 3：趋势分析（积累 1 周数据后）

1. 实现周环比趋势计算
2. 添加趋势箭头和状态灯指示
3. 开始识别高效时段模式

### Phase 4：智能建议（积累 2-4 周数据后）

1. 部署建议规则引擎
2. 实现习惯模式识别
3. 自动生成个性化改善建议
4. 周报自动聚合

## 五、关键原则

1. **渐进式实施：** 不要一次上全部功能，从最核心的 4 个指标开始，逐步增加复杂度
2. **数据不说谎：** 所有建议必须基于实际数据，不要凭感觉。有数据支撑的观察比空泛建议有用 100 倍
3. **可执行 > 全面：** 日报中的建议必须是明天就能采取行动的具体事项，不要写"注意提高效率"这种废话
4. **尊重节奏：** 每个人有自己的生物节律和工作偏好，框架要适应人而不是人适应框架
5. **简洁优先：** 日报控制在 2 分钟内能读完。详细数据放在附录或单独文件中，日报只呈现关键洞察
6. **反馈闭环：** Try 项目必须在后续日报中追踪效果，形成"问题→尝试→验证→保持/放弃"的闭环
