# 个人生产力工具集成调研报告

> 调研日期：2026-02-08
> 目的：评估可集成到 Luna（OpenClaw AI 助手）的个人生产力工具，提出推荐方案和优先级

---

## 一、调研背景

Luna 目前已集成的工具链包括：
- **Lark（飞书）**：日历、文档、消息、Wiki
- **邮件**：Gmail 收发
- **浏览器**：网页浏览和自动化
- **文件系统**：本地 workspace 读写
- **Cron 任务**：定时检查、日报生成等

这些能力覆盖了"沟通"和"信息管理"两大场景，但在 **任务管理**、**知识积累**、**时间追踪** 和 **习惯养成** 等个人生产力维度上仍有空白。本报告对主流工具进行系统评估，重点关注 API 可集成性和与现有工具链的互补性。

---

## 二、工具生态全景分析

### 2.1 任务管理类

#### Todoist ⭐⭐⭐⭐⭐

- **概述**：全球最流行的个人任务管理工具之一，专注于简洁高效的 GTD 风格任务管理。支持自然语言输入、标签、优先级、项目嵌套、过滤器等。
- **API 情况**：
  - 提供统一的 **Todoist API v1**（2025年从 REST v2 + Sync v9 合并升级而来）
  - REST 风格，支持 OAuth2 和 Personal Token 认证
  - 完整的 CRUD：任务、项目、标签、评论、过滤器
  - 支持 Webhook（任务完成、创建等事件推送）
  - 速率限制宽松（个人使用完全够用）
  - 文档质量：优秀，有丰富的代码示例
- **定价**：免费版即可使用 API；Pro 版 $5/月解锁高级功能（提醒、过滤器等）
- **与 Luna 集成价值**：⭐⭐⭐⭐⭐
  - Carl 可以通过自然语言告诉 Luna 添加/查询/完成任务
  - Luna 可以主动检查到期任务并提醒
  - 可与 Lark 日历联动（任务截止日期 → 日历事件）
  - 日报中可自动统计当天完成的任务数

#### TickTick ⭐⭐⭐⭐

- **概述**：功能强大的任务管理 + 习惯追踪 + 番茄钟一体化工具，在亚洲用户中非常流行。
- **API 情况**：
  - **API 支持有限**：官方 API 不公开，没有完善的开发者文档
  - 仅通过 IFTTT、Zapier 等中间件提供间接集成
  - 无原生 Webhook 支持
  - 社区有人通过逆向工程实现非官方 API（不稳定、有风险）
- **定价**：免费版功能丰富；Premium $35.99/年
- **与 Luna 集成价值**：⭐⭐
  - 功能本身很优秀，但 API 封闭是硬伤
  - 除非通过 IFTTT 间接操作，否则无法可靠集成
  - **不推荐**：集成成本高、稳定性差

#### Things 3 ⭐⭐⭐

- **概述**：Apple 生态最优雅的任务管理应用，设计精良，获奖无数。
- **API 情况**：
  - **无 REST API**，仅支持 AppleScript（macOS）和 Shortcuts（iOS）
  - 提供 URL Scheme（`things:///add?title=xxx`）用于创建任务
  - 无法远程调用，必须在本地 Apple 设备上执行
- **定价**：一次性购买（Mac $49.99，iPhone $9.99，iPad $19.99）
- **与 Luna 集成价值**：⭐⭐
  - Luna 运行在云端服务器，无法直接调用 AppleScript
  - 可通过 Node 设备间接操作（如果 Carl 的 Mac 连接为 Node）
  - **不推荐作为主要集成目标**：生态封闭

#### Microsoft To Do ⭐⭐⭐

- **概述**：微软出品，与 Outlook、Teams 深度集成。
- **API 情况**：
  - 通过 **Microsoft Graph API** 访问
  - 支持完整的任务 CRUD、列表管理
  - OAuth2 认证，文档完善
  - 但 Graph API 权限体系复杂，需要 Azure AD 注册应用
- **定价**：完全免费
- **与 Luna 集成价值**：⭐⭐⭐
  - API 能力强，但如果 Carl 主要在 Google/Lark 生态中，增加 Microsoft 依赖意义不大
  - 更适合已在 Microsoft 365 生态中的用户

### 2.2 笔记/知识管理类

#### Notion ⭐⭐⭐⭐⭐

- **概述**：全能型工作空间，笔记、数据库、Wiki、项目管理一体化。用户量巨大，社区活跃。
- **API 情况**：
  - **Notion API** 功能完善，2025年9月更新到 v2025-09-03 版
  - 支持页面 CRUD、数据库查询/创建/更新、块级内容操作
  - OAuth2 集成或 Internal Integration Token
  - 搜索 API 支持全文检索
  - 新版 API 引入 Data Source 概念，更灵活但有 breaking changes
  - 速率限制：3 requests/second（个人使用足够）
  - 文档质量：优秀
- **定价**：免费版即可使用 API；Plus $10/月
- **与 Luna 集成价值**：⭐⭐⭐⭐
  - 可作为"第二大脑"——Luna 帮助整理笔记、检索知识
  - 数据库功能可做 CRM、读书记录、项目跟踪等
  - **潜在冲突**：与 Lark Wiki/Docs 有功能重叠，需评估是否会造成信息分散
  - 建议：如果 Carl 已经在用 Notion 则高价值；如果主用 Lark 则慎重

#### Obsidian ⭐⭐⭐

- **概述**：本地优先的 Markdown 知识管理工具，双向链接、图谱视图，隐私性极强。
- **API 情况**：
  - **无官方云端 API**——Obsidian 是本地应用
  - 桌面版有本地 HTTP API（端口 12315，需手动开启）
  - 有 MCP Server 实现（mcp-pkm-logseq），但限于本地运行
  - 插件生态丰富（社区有 Todoist、Toggl 等插件）
  - 文件本质是 Markdown，可通过文件系统直接操作
- **定价**：免费（核心功能）；Sync $4/月、Publish $8/月
- **与 Luna 集成价值**：⭐⭐⭐
  - 如果 Carl 用 Obsidian，Luna 可以通过 Sync 或文件系统读写 Markdown 文件
  - 适合作为 Luna 的"本地知识库"后端
  - **限制**：需要 Carl 的设备在线并运行 Obsidian（或配置同步）
  - 实际上 Luna 的 workspace 文件系统已经是类似的本地知识库

#### Logseq ⭐⭐⭐

- **概述**：开源的大纲式知识管理工具，类似 Roam Research，支持双向链接和图谱。
- **API 情况**：
  - 桌面版提供 **本地 HTTP API**（默认端口 12315，需手动开启）
  - 已有 MCP Server 实现（mcp-pkm-logseq），支持通过 AI 助手操作
  - 但 API 仅在 Logseq 桌面应用运行时可用
  - 无云端 API
- **定价**：完全免费开源
- **与 Luna 集成价值**：⭐⭐
  - 与 Obsidian 类似的限制：依赖本地运行
  - 社区较小，集成成熟度不如 Notion/Obsidian
  - **不推荐优先集成**

### 2.3 时间追踪类

#### Toggl Track ⭐⭐⭐⭐⭐

- **概述**：最流行的时间追踪工具之一，界面简洁，一键开始/停止计时。支持项目、客户端、标签分类。
- **API 情况**：
  - **完善的 REST API**（V9）
  - 支持时间条目的 CRUD、项目/客户端/工作区管理
  - API Key 认证或 OAuth2
  - 支持启动/停止当前计时器
  - 报告 API：可拉取详细的时间分析报告
  - 集成 100+ 工具（包括 Slack 等）
  - 2025年底新增 AI Bot 功能（Slack 集成）
  - 速率限制合理
- **定价**：免费版（最多5人）API 完全可用；Starter $10/用户/月
- **与 Luna 集成价值**：⭐⭐⭐⭐⭐
  - Carl 可以语音/文字告诉 Luna "开始计时：写代码"
  - Luna 可在日报中自动拉取当天时间分配数据
  - 与 Lark 日历结合，自动分析会议时间 vs 深度工作时间
  - 周报可自动生成时间分析图表
  - **高价值低成本的集成**

#### Clockify ⭐⭐⭐⭐

- **概述**：完全免费的时间追踪工具（无用户数限制），功能与 Toggl 类似。
- **API 情况**：
  - **REST API** 完善，文档质量好
  - API Key 认证
  - 支持时间条目、项目、客户端、标签的完整 CRUD
  - 支持计时器启停
  - 报告 API 可用
  - Webhook 支持
- **定价**：核心功能完全免费（包括 API 访问）
- **与 Luna 集成价值**：⭐⭐⭐⭐
  - 功能与 Toggl 类似，优势是完全免费
  - 如果 Carl 不需要 Toggl 的高级分析功能，Clockify 是更经济的选择
  - **推荐作为 Toggl 的替代方案**

#### RescueTime ⭐⭐⭐

- **概述**：自动追踪工具，在后台记录你使用每个应用/网站的时间，无需手动操作。
- **API 情况**：
  - 有 API 但文档更新不频繁
  - 主要提供数据读取（生产力评分、应用使用时间等）
  - 不支持写入操作（自动追踪的定位）
  - 2025年重新定位为 "RescueTime Focus"，强调专注模式和干扰拦截
- **定价**：Focus $12/月；Focus + Timesheets $20/月
- **与 Luna 集成价值**：⭐⭐⭐
  - 只读集成：Luna 可拉取 Carl 的每日生产力数据并放入日报
  - 与 Toggl 互补：Toggl 记录"你想做什么"，RescueTime 记录"你实际做了什么"
  - **可作为增强型集成，但不是核心**

### 2.4 习惯养成类

#### Habitica ⭐⭐⭐⭐

- **概述**：开源的游戏化习惯追踪器，将日常习惯变成 RPG 冒险。支持习惯（Habits）、每日任务（Dailies）、待办事项（To-Dos）。
- **API 情况**：
  - **完整的 REST API**，文档详尽（habitica.com/apidoc）
  - 支持任务 CRUD、习惯打卡、用户状态查询
  - API Key + User ID 认证（简单直接）
  - 开源项目，社区活跃
  - Home Assistant 已有集成（说明 API 成熟度高）
  - 有 API 使用指南和第三方工具准则
- **定价**：完全免费（可选购虚拟宝石支持开发）
- **与 Luna 集成价值**：⭐⭐⭐⭐
  - Carl 可以让 Luna 帮他打卡："今天跑步了"、"今天读了30分钟书"
  - Luna 可在日报中展示习惯完成情况和连续打卡天数
  - 游戏化元素增加趣味性
  - **轻量级集成，API 简单可靠**

#### Streaks ⭐⭐

- **概述**：Apple 生态下最简洁的习惯追踪应用，Apple Design Award 获奖。
- **API 情况**：
  - **无公开 API**
  - 仅支持 Apple Shortcuts
  - 数据仅存储在 iCloud
- **与 Luna 集成价值**：⭐
  - 无法远程集成
  - **不推荐**

## 四、与现有工具链的冲突与互补分析

### 功能重叠风险

| 新工具 | 与现有工具冲突 | 程度 | 建议 |
|--------|---------------|------|------|
| Notion | Lark Docs / Wiki | 🟡 中 | 如 Carl 主用 Lark 做文档，Notion 会造成信息分散。建议选择其一 |
| Todoist | 无直接冲突 | 🟢 低 | Lark 本身的任务管理功能弱，Todoist 是很好的补充 |
| Toggl | 无冲突 | 🟢 无 | Lark 没有时间追踪功能，完全互补 |
| Habitica | 无冲突 | 🟢 无 | 全新维度的功能，完全互补 |
| RescueTime | 无冲突 | 🟢 无 | 被动追踪，与主动工具不冲突 |

### 互补性矩阵

```
现有能力                    缺失能力（推荐工具填补）
────────────                ─────────────────────────
✅ 日程管理（Lark 日历）     ❌ 任务管理 → Todoist
✅ 沟通（Lark/邮件）         ❌ 时间追踪 → Toggl Track
✅ 文档（Lark Docs/Wiki）   ❌ 习惯养成 → Habitica
✅ 网页信息获取              ❌ 自动屏幕时间统计 → RescueTime
✅ 本地文件管理              ❌ 结构化知识库 → Notion（可选）
```

## 五、推荐方案：Top 5 集成工具

### 🥇 第一优先级：Todoist（任务管理）

**推荐理由：**
- API 成熟度最高，文档最完善，社区最大
- 填补了 Luna 最关键的缺失能力——个人任务管理
- 集成成本极低（几小时即可完成基础版）
- 自然语言任务解析与 Luna 的对话能力完美契合

**集成场景：**
- "帮我记一下：周五之前提交报告" → 创建带截止日期的任务
- "我今天有什么要做的？" → 查询今日任务
- "报告写完了" → 标记任务完成
- 日报自动统计：今日完成 X 项任务，待办 Y 项
- 到期提醒通过 Lark/邮件推送

**预估开发时间：** 1-2 天（基础 CRUD）+ 1 天（智能提醒）

---

### 🥈 第二优先级：Toggl Track（时间追踪）

**推荐理由：**
- API 简洁可靠，启停计时器只需一个 API 调用
- 时间数据可极大增强日报/周报质量
- 与 Lark 日历互补——日历记录"计划"，Toggl 记录"实际"
- 帮助 Carl 建立时间意识

**集成场景：**
- "开始工作：写代码" → 启动 Toggl 计时器
- "停" → 停止当前计时器
- "我今天在什么上花了最多时间？" → 查询时间报告
- 日报自动生成时间分配饼图
- 周报对比：计划时间 vs 实际时间

**预估开发时间：** 1 天（基础功能）+ 1 天（报告集成）

---

### 🥉 第三优先级：Habitica（习惯养成）

**推荐理由：**
- 免费、开源、API 简单
- 游戏化元素增加使用趣味性
- 与任务管理是不同维度——习惯是重复性的，任务是一次性的
- Luna 可以成为"习惯教练"角色

**集成场景：**
- "今天运动了" → 打卡运动习惯 → 获得经验值
- 日报展示：习惯连续打卡天数、角色等级
- Luna 主动鼓励："你已经连续跑步7天了，继续加油！🏃"
- 每日 Dailies 未完成时提醒

**预估开发时间：** 1 天

---

### 4️⃣ 第四优先级：Notion（知识管理）— 有条件推荐

**推荐理由：**
- API 功能最强大，数据库能力远超其他工具
- 适合做"结构化知识库"：读书笔记、项目文档、个人 CRM 等
- 如果 Carl 已在使用 Notion，集成价值极高

**条件：**
- ⚠️ 如果 Carl 主要用 Lark 做文档管理，增加 Notion 会导致信息分散
- 建议在确认 Carl 使用场景后再决定是否集成
- 或者将 Notion 定位为"个人知识库"，Lark 定位为"工作协作"，做好分工

**集成场景：**
- "帮我记到 Notion：今天学到了 XX" → 创建笔记
- "查一下我之前关于 YY 的笔记" → 搜索 Notion
- 自动将 Luna 的研究成果同步到 Notion 数据库

**预估开发时间：** 2-3 天（API 复杂度较高）

---

### 5️⃣ 第五优先级：Clockify（Toggl 替代方案）

**推荐理由：**
- 如果 Carl 不想付费，Clockify 是完全免费的 Toggl 替代
- API 能力相当，集成方式几乎相同
- 建议二选一：Toggl 或 Clockify

**预估开发时间：** 与 Toggl 相同

## 六、集成路线图建议

```
Phase 1（本周）: Todoist 集成
  → 基础 CRUD + 到期提醒 + 日报统计
  → 让 Carl 立刻感受到"任务管理"能力

Phase 2（下周）: Toggl Track 集成
  → 计时器启停 + 日报时间分析
  → 与 Phase 1 联动：完成 Todoist 任务时自动停止 Toggl 计时

Phase 3（两周后）: Habitica 集成
  → 习惯打卡 + 游戏化展示
  → 轻松有趣的增强

Phase 4（按需）: Notion 集成
  → 取决于 Carl 的使用习惯
  → 确认不与 Lark 冲突后再实施
```

## 七、技术实现考量

### OpenClaw Skill 开发
每个工具建议独立开发为一个 OpenClaw Skill：
- `skill-todoist/`: 任务管理能力
- `skill-toggl/`: 时间追踪能力
- `skill-habitica/`: 习惯追踪能力

### API 密钥管理
- 所有 API Key/Token 存储在 OpenClaw 的环境变量或 secrets 中
- 不硬编码在代码里
- OAuth2 流程需要 Carl 一次性授权

### 错误处理
- API 调用失败时优雅降级
- 速率限制保护
- Token 过期自动刷新（OAuth2 场景）

### 数据隔离
- 生产力工具中可能包含敏感的个人数据
- 仅在需要时查询，不做全量同步
- 遵循 Luna 现有的安全策略

## 八、结论

在评估了 11 个主流生产力工具后，我们推荐优先集成 **Todoist**（任务管理）和 **Toggl Track**（时间追踪），这两个工具 API 成熟、集成成本低、与现有工具链完全互补，且能立刻为 Carl 的日常工作带来可感知的效率提升。

**Habitica** 作为第三优先级，可以为 Luna 增加有趣的"习惯教练"角色。**Notion** 则视 Carl 的使用习惯而定，避免与 Lark 产生冲突。

总体原则：**先补短板（任务+时间），再做增强（习惯+知识），始终避免工具过载**。
