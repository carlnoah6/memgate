# 对齐与后训练：SFT、RLHF、DPO、Constitutional AI 及新兴方法对比

> 研究日期：2026-02-08
> 系列：从零训练 LLM + 视觉模型 · 第 8 篇
> 关键词：SFT, RLHF, PPO, DPO, Constitutional AI, RLAIF, GRPO, RLVR, ORPO, KTO, SimPO

---

## 一、引言：为什么需要对齐与后训练？

大语言模型（LLM）在预训练阶段通过海量文本学习了语言的统计规律和世界知识，但预训练模型本质上只是一个"文本补全机器"——它会续写最可能出现的下一个 token，而不是生成对用户有帮助、安全、准确的回答。

后训练（Post-training）是将预训练模型转化为可用产品的关键环节。其核心目标包括：

1. **遵循指令**：让模型理解并执行用户的具体请求，而非简单地续写文本
2. **有用性（Helpfulness）**：生成准确、详细、有价值的回答
3. **安全性（Harmlessness）**：拒绝生成有害、危险或不当内容
4. **诚实性（Honesty）**：在不确定时承认自己的局限，不编造事实

后训练通常分为两大阶段：**监督微调（SFT）** 和 **偏好对齐（Preference Alignment）**。偏好对齐的方法又可以细分为基于强化学习的方法（如 RLHF/PPO）、直接偏好优化方法（如 DPO 及其变体）、以及基于 AI 反馈的方法（如 Constitutional AI）。

下面我们逐一深入分析每种方法的原理、实现细节、优缺点，以及最新的研究进展。

## 二、监督微调（Supervised Fine-Tuning, SFT）

### 2.1 核心原理

SFT 是后训练的第一步，也是最直观的方法。其核心思想非常简单：收集高质量的（指令, 回答）配对数据，然后用标准的下一 token 预测损失（cross-entropy loss）微调预训练模型。

数学上，给定数据集 D = {(x_i, y_i)}，优化目标为：

```
L_SFT = -E_(x,y)~D [ Σ_t log π_θ(y_t | x, y_{<t}) ]
```

其中 π_θ 是模型参数化的策略（policy），x 是指令/提示，y 是期望的回答。

### 2.2 指令数据的构建

SFT 数据的质量远比数量重要。研究表明，少量高质量数据（如 1000-50000 条）往往比大量低质量数据更有效。

**主要数据来源：**

- **人工标注**：由专业标注员编写指令和回答，质量最高但成本也最高。OpenAI 的 InstructGPT 使用了约 13,000 条人工标注数据。
- **众包与开源**：如 OpenAssistant、Dolly、ShareGPT 等社区贡献的数据集。
- **合成数据（Self-Instruct）**：使用已有的强大模型（如 GPT-4）生成指令-回答对。Alpaca 项目首次大规模使用了这种方法，用 GPT-3.5 生成了 52,000 条指令数据。
- **混合策略**：现代方法通常结合多种来源。例如 Llama 3.1 使用了人工标注 + 合成数据 + 拒绝采样的混合方案。

**数据质量的关键发现（2024-2025 最新研究）：**

- **LIMA 论文** 证明仅 1,000 条精心筛选的高质量数据就能让模型达到接近 GPT-4 的对话能力，提出了著名的 "Less Is More for Alignment" 原则。
- **GRAPE（2025）** 研究表明，最好的 SFT 数据是那些与预训练分布匹配的数据——用 1/3 的数据量和一半的训练轮次就能超过 Tulu3-SFT 3.5% 的表现。
- **Token 级质量评分**：最新研究引入了 token 级别的质量打分机制，将数据中的 token 分为"正面（信息性）"和"负面（误导性）"两类，分别加权训练。

### 2.3 SFT 的最佳实践

1. **数据多样性**：覆盖多种任务类型（问答、创意写作、代码、数学推理等）
2. **回答质量 > 数量**：选择更长、更详细的回答作为训练目标
3. **聊天模板格式化**：使用模型对应的 chat template（如 `<|user|>` `<|assistant|>` 标记），确保格式一致
4. **学习率选择**：通常比预训练低 1-2 个数量级，典型值为 1e-5 到 2e-4
5. **训练轮次**：通常 1-3 个 epoch 即可，过多容易过拟合
6. **参数高效微调**：可使用 LoRA/QLoRA 等方法降低计算成本

### 2.4 SFT 的局限性

SFT 的根本局限在于它只能"模仿"训练数据中的回答风格，而无法真正学会区分"好回答"和"坏回答"。具体来说：

- **无法表达负面偏好**：SFT 只告诉模型"应该怎么回答"，但没有告诉它"不应该怎么回答"
- **分布偏移问题**：模型在推理时会遇到训练中没见过的指令，可能产生不符合期望的输出
- **"最高公约数"效应**：如果训练数据中对同一问题有多种不同质量的回答，SFT 倾向于学习它们的"平均值"，而非最佳回答

这些局限性正是偏好对齐方法（RLHF、DPO 等）存在的意义。

## 三、基于人类反馈的强化学习（RLHF）

### 3.1 核心原理

RLHF（Reinforcement Learning from Human Feedback）是由 OpenAI 在 InstructGPT（2022）和 ChatGPT 中推广的对齐方法。它的核心思想是：先从人类偏好数据中训练一个奖励模型（Reward Model），然后用强化学习算法（通常是 PPO）优化语言模型的策略，使其生成的回答获得更高的奖励。

RLHF 的完整流程分为三个阶段：

**阶段 1：监督微调（SFT）**
如上一节所述，先用高质量指令数据微调基座模型，得到 SFT 模型 π_SFT。

**阶段 2：奖励模型训练**
- 收集偏好数据：给定同一指令 x，让模型生成多个回答，由人类标注员排序或成对比较
- 训练奖励模型 R_φ(x, y)：输入指令和回答，输出一个标量分数
- 使用 Bradley-Terry 模型建模偏好概率：P(y_w > y_l) = σ(R_φ(x, y_w) - R_φ(x, y_l))
- 最小化交叉熵损失训练奖励模型

**阶段 3：PPO 策略优化**
使用 PPO（Proximal Policy Optimization）算法优化语言模型策略 π_θ：

```
max_θ E_{x~D, y~π_θ(·|x)} [ R_φ(x, y) - β · KL(π_θ(·|x) || π_SFT(·|x)) ]
```

其中 KL 散度项防止模型偏离 SFT 策略太远（避免 reward hacking）。

### 3.2 PPO 的实现细节

PPO 在 LLM 场景下的实现非常复杂，需要同时在显存中维护四个模型：

1. **策略模型（Policy）**：正在训练的 LLM
2. **参考模型（Reference）**：冻结的 SFT 模型副本，用于计算 KL 散度
3. **奖励模型（Reward Model）**：预训练好的标量奖励预测器
4. **价值模型（Value Function）**：估计状态价值，用于计算优势函数（advantage）

这意味着对于一个 7B 参数的模型，PPO 训练需要在显存中加载约 28B 参数量的模型（假设每个模型大小相同）。这是 RLHF 训练成本高昂的主要原因之一。

**关键超参数：**
- β（KL 惩罚系数）：通常 0.01-0.2，控制策略与参考模型的偏离程度
- PPO clip range：通常 0.2，限制每次更新的幅度
- GAE（广义优势估计）的 λ 参数：通常 0.95
- Mini-batch 大小和更新轮次

### 3.3 奖励黑客（Reward Hacking）问题

RLHF 最严重的问题之一是 **奖励黑客**：模型学会利用奖励模型的漏洞获取高分，但实际输出质量并未提升。常见表现包括：

- **长度偏好**：生成更长的回答以获得更高奖励（人类标注员倾向于偏好更长回答）
- **谄媚（Sycophancy）**：一味迎合用户观点而非给出客观回答
- **格式利用**：大量使用列表、加粗等格式来提升奖励分数
- **语义欺骗**：生成听起来自信但实际不准确的内容

**缓解策略：**
- KL 散度约束（最基础的方法）
- 奖励模型集成（多个奖励模型取平均）
- ODIN（正交解耦激励）：将奖励分解为长度相关和内容相关两部分
- 信息瓶颈方法：过滤掉与内容质量无关的噪声信号
- 定期更新奖励模型以跟上策略变化

### 3.4 RLHF 的实际应用

**成功案例：**
- OpenAI 的 ChatGPT/GPT-4 系列
- Anthropic 的 Claude 系列
- Google 的 Gemini（内部使用 RLHF 变体）

**工具框架：**
- OpenRLHF：基于 Ray + vLLM 的分布式 RLHF 框架
- TRL（Transformers Reinforcement Learning）：HuggingFace 的 RLHF 实现
- DeepSpeed-Chat：集成了 SFT → 奖励模型 → PPO 的完整流程

### 3.5 RLHF 的优缺点总结

| 维度 | 评价 |
|------|------|
| 效果上限 | ⭐⭐⭐⭐⭐ 目前最强的闭源模型几乎都使用 RLHF |
| 实现复杂度 | ⭐⭐⭐⭐⭐ 非常复杂，需要大量工程经验 |
| 计算成本 | ⭐⭐⭐⭐⭐ 需要 4 个模型同时在显存中 |
| 训练稳定性 | ⭐⭐⭐ 容易出现奖励黑客和模式坍塌 |
| 人力成本 | ⭐⭐⭐⭐ 需要大量高质量人类标注 |

## 四、直接偏好优化（Direct Preference Optimization, DPO）

### 4.1 核心原理

DPO 是 2023 年由 Stanford 的 Rafailov 等人提出的方法，其核心洞察是：**RLHF 的最优策略可以用一个封闭形式的表达式来表示，因此可以跳过奖励模型训练和 PPO 优化，直接在偏好数据上优化语言模型**。

DPO 的数学推导非常优雅。从 RLHF 的优化目标出发：

```
max_π E_{x,y~π} [R(x,y)] - β · KL(π || π_ref)
```

最优策略的封闭解为：

```
π*(y|x) = (1/Z(x)) · π_ref(y|x) · exp(R(x,y)/β)
```

反解奖励函数：

```
R(x,y) = β · log(π*(y|x) / π_ref(y|x)) + β · log Z(x)
```

将其代入 Bradley-Terry 偏好模型，得到 DPO 的损失函数：

```
L_DPO = -E_{(x, y_w, y_l)} [log σ(β · (log(π_θ(y_w|x)/π_ref(y_w|x)) - log(π_θ(y_l|x)/π_ref(y_l|x))))]
```

直觉上，DPO 的目标是：提高好回答（y_w）相对于参考模型的概率比，同时降低差回答（y_l）相对于参考模型的概率比。

### 4.2 DPO 的训练实践

**数据格式**：每条训练样本包含三个字段：
- `prompt`（指令/问题）
- `chosen`（人类偏好的好回答）
- `rejected`（人类不偏好的差回答）

**关键超参数：**
- β（温度参数）：通常 0.1-0.5，控制偏离参考模型的程度。β 越大，偏离越小。
- 学习率：通常比 SFT 低 10-100 倍，典型值为 1e-6 到 5e-6
- 训练轮次：1-3 个 epoch

**在线 vs 离线 DPO：**
- **离线 DPO**：使用预先收集的静态偏好数据集训练，计算效率更高
- **在线 DPO**：在训练过程中让当前策略生成回答，然后用奖励模型或规则打分来构造偏好对。效果通常更好，但成本更高
- 实际应用中，Qwen 2 采用了两阶段方法：先离线 DPO，再在线 DPO（拒绝采样）

**关于 on-policy vs off-policy 数据的研究发现：**
Phil Schmid（2025）的实验表明，使用模型自身生成的 on-policy 数据进行 DPO 训练效果明显优于使用其他模型生成的 off-policy 数据。这意味着最佳实践是：先做 SFT，然后用 SFT 模型生成多个回答，再用奖励模型或人工筛选构造偏好对。

### 4.3 DPO 的优缺点

**优势：**
- 实现简单：无需训练单独的奖励模型，无需 PPO，像 SFT 一样简单
- 计算高效：只需 2 个模型（当前策略 + 冻结的参考模型），显存占用仅为 RLHF 的一半
- 训练稳定：没有 RL 训练的不稳定性问题
- 效果优秀：在多数 benchmark 上与 RLHF/PPO 效果相当

**局限：**
- 对数据质量高度敏感：偏好数据的质量直接决定训练效果
- 离线方法的天然限制：静态数据集无法覆盖策略在训练中的变化
- 冗长偏差（verbosity bias）：DPO 训练后的模型倾向于生成更冗长的回答
- 理论上的次优性：相比 RLHF 的在线优化，离线 DPO 可能不够灵活

**行业现状（2025-2026）：**
- 开源模型领域：DPO 是最流行的对齐方法，几乎所有 HuggingFace 排行榜上的模型都使用了 DPO
- 闭源模型领域：OpenAI（ChatGPT）和 Anthropic（Claude）仍然主要使用 RLHF/PPO，可能因为在其规模下 RLHF 的效果上限更高
- 趋势：SFT + DPO 已成为开源社区的"标准配方"

## 五、Constitutional AI（CAI）与 RLAIF

### 5.1 Constitutional AI 的核心思想

Constitutional AI 是 Anthropic 于 2022 年底提出的方法，旨在减少对人类标注的依赖，同时提高模型的安全性和可控性。其核心思想是：**用一组明确的原则（"宪法"）指导 AI 的自我批判和自我修正**。

"宪法"是一组用自然语言表述的原则，例如：
- "请选择最有帮助、最准确、最无害的回答"
- "选择不鼓励暴力或威胁的回答"
- "选择最尊重用户自主权的回答"

### 5.2 CAI 的两个阶段

**阶段 1：监督式自我修正（Supervised Self-Critique）**
1. 用初始模型生成回答（包括可能有害的回答）
2. 让模型基于宪法原则对自己的回答进行"自我批评"
3. 让模型基于批评修改自己的回答
4. 用修改后的回答作为 SFT 训练数据微调模型

这个过程可以迭代多轮，每轮都让回答更加符合宪法原则。

**阶段 2：RLAIF（Reinforcement Learning from AI Feedback）**
1. 让微调后的模型生成多个回答
2. 让另一个 AI 模型（而非人类）基于宪法原则选择更好的回答
3. 用 AI 的偏好数据训练奖励模型
4. 用 RLHF 的标准流程（PPO）优化最终模型

### 5.3 RLAIF vs RLHF

RLAIF 的核心价值在于**可扩展性**：

| 维度 | RLHF | RLAIF |
|------|------|-------|
| 标注成本 | 高（需要人类标注员） | 低（AI 自动标注） |
| 标注速度 | 慢（受限于人力） | 快（可并行扩展） |
| 标注一致性 | 低（不同标注员可能不一致） | 高（同一模型 + 同一原则 = 一致结果） |
| 可解释性 | 低（人类偏好难以量化解释） | 高（宪法原则明确可审计） |
| 质量上限 | 取决于标注员能力 | 取决于 AI 模型能力 |
| 覆盖范围 | 受限于标注样本量 | 可以大规模生成 |

Google 的研究也表明，在很多场景下 RLAIF 的效果可以接近甚至匹配 RLHF。

### 5.4 CAI 的意义与局限

**意义：**
- 提供了一种可审计、可解释的对齐方法
- 大幅降低了人类标注的需求
- 宪法原则可以根据不同文化、法规灵活调整
- 为 AI 安全治理提供了实际可操作的框架

**局限：**
- 宪法原则的设计本身需要人类专家的深思熟虑
- AI 模型的判断能力仍然有限，可能会产生系统性偏差
- "AI 评判 AI" 存在循环依赖的风险
- 目前主要由 Anthropic 实践，社区复现和验证的工作还不够充分

## 六、DPO 的变体与新兴方法

2024-2025 年间，研究社区提出了大量 DPO 的改进变体，形成了丰富的后训练方法生态。

### 6.1 IPO（Identity Preference Optimization）

IPO 解决了 DPO 的一个理论问题：DPO 假设成对偏好可以用逐点奖励（pointwise reward）替代，但这个假设并不总是成立。IPO 使用了一种更严谨的理论框架来避免这个问题。

### 6.2 KTO（Kahneman-Tversky Optimization）

受经济学中前景理论启发，KTO 最大的特点是**不需要成对的偏好数据**，只需要对每个回答标注"好"或"差"的二元标签。这大大降低了数据收集的难度。

**优势：**
- 数据收集简单：只需二元标签而非成对比较
- 对标签噪声鲁棒：基于人类损失厌恶的心理学模型
- 适合冷启动场景：当偏好数据稀缺时特别有用

**局限：**
- 二元标签缺乏成对比较的细粒度信息
- 相对较新，最佳实践仍在探索中

### 6.3 ORPO（Odds Ratio Preference Optimization）

ORPO 的核心创新是**将 SFT 和偏好对齐合并为一个步骤**，消除了分开训练的需要。它通过在负对数似然损失上附加一个简单的对数几率比（log odds ratio）项来实现：

```
L_ORPO = L_NLL + λ · L_OR
```

其中 L_OR 对不期望的回答施加轻微惩罚，对期望的回答施加强适应信号。

**优势：**
- 无需参考模型（节省显存）
- 单步完成 SFT + 对齐（节省训练时间）
- 某些 benchmark 上超过 RLHF 和 DPO

**案例：** HuggingFace 的 Zephyr-141B-A35B 使用 ORPO 训练。

### 6.4 SimPO（Simple Preference Optimization）

SimPO 是 2024 年 5 月提出的方法，核心改进是使用**长度归一化的序列概率**作为隐式奖励，而不是 DPO 中需要参考模型的对数概率比。

```
r_SimPO(x, y) = (1/|y|) · log π_θ(y|x)
```

**优势：**
- 无需参考模型（节省约 50% 显存）
- 训练更稳定
- 在多个 benchmark 上超过 DPO

### 6.5 GRPO 与 RLVR：推理模型的新范式

2025 年，DeepSeek-R1 的发布引发了对 **GRPO（Group Relative Policy Optimization）** 和 **RLVR（Reinforcement Learning with Verifiable Rewards）** 的广泛关注。

**GRPO 的核心思想：**
- 去除了 PPO 中的价值模型（Value Model），用组内采样的统计信息替代
- 对每个问题采样一组回答（如 8-64 个），计算组内平均奖励作为基线
- 用回答奖励相对于基线的偏差作为优势估计
- 大幅降低了显存需求（3 个模型 → 2 个模型）

**RLVR 的核心思想：**
- 用**可验证的奖励函数**替代学习的奖励模型
- 适用于有明确正确答案的任务（数学、编程、逻辑推理）
- 例如：数学题可以直接验证答案是否正确（二元奖励）
- 彻底消除了奖励黑客的问题（因为奖励是真实的，而非学习的近似）

**DeepSeek-R1-Zero 的里程碑：**
- 完全不经过 SFT，直接从基座模型用 GRPO + RLVR 训练
- 模型自发地涌现出长链推理（Chain-of-Thought）能力
- 证明了 RL 本身可以激发推理能力，而不仅仅是"对齐"

**DeepSeek-R1 的完整流程：**
1. 冷启动 SFT（少量高质量推理数据）
2. GRPO + RLVR 大规模推理训练
3. 拒绝采样 + SFT（用 RL 模型生成数据微调新模型）
4. 最终 RL 对齐（结合推理和通用任务）

这一范式标志着后训练从"对齐（alignment）"向"能力增强（capability elicitation）"的重要转变。

## 七、方法对比总结

### 7.1 总览表

| 方法 | 需要奖励模型 | 需要 RL | 需要参考模型 | 模型数量 | 数据格式 | 实现难度 | 适用场景 |
|------|:---:|:---:|:---:|:---:|------|:---:|------|
| SFT | ✗ | ✗ | ✗ | 1 | (指令, 回答) | ⭐ | 基础指令跟随 |
| RLHF/PPO | ✓ | ✓ | ✓ | 4 | 成对偏好 | ⭐⭐⭐⭐⭐ | 顶级闭源模型 |
| DPO | ✗ | ✗ | ✓ | 2 | 成对偏好 | ⭐⭐ | 开源模型主流 |
| CAI/RLAIF | ✓(AI) | ✓ | ✓ | 4 | 宪法原则 | ⭐⭐⭐⭐ | 安全性优先 |
| KTO | ✗ | ✗ | ✓ | 2 | 二元标签 | ⭐⭐ | 数据稀缺 |
| ORPO | ✗ | ✗ | ✗ | 1 | 成对偏好 | ⭐ | 资源受限 |
| SimPO | ✗ | ✗ | ✗ | 1 | 成对偏好 | ⭐ | 资源受限 |
| GRPO+RLVR | ✗(规则) | ✓ | ✓ | 2-3 | 可验证任务 | ⭐⭐⭐ | 推理能力训练 |

### 7.2 选型建议

**如果你是个人开发者或小团队（1-8 GPU）：**
→ SFT + DPO/SimPO/ORPO 是最佳选择，简单高效

**如果你追求顶级效果且有充足资源：**
→ SFT + RLHF/PPO 仍然是效果天花板最高的方法

**如果你的目标模型需要强推理能力（数学/编程）：**
→ SFT + GRPO/RLVR 是 2025 年的最新最佳实践（DeepSeek-R1 路线）

**如果你优先考虑安全性和可控性：**
→ Constitutional AI + RLAIF 提供了最好的可审计性

**如果你的偏好数据非常有限：**
→ KTO 只需二元标签，数据收集成本最低

## 八、实际部署的后训练流水线

综合当前（2025-2026）的行业最佳实践，一个完整的后训练流水线通常如下：

### 阶段 1：SFT（冷启动）
- 数据量：10K-500K 高质量指令-回答对
- 训练：1-3 epoch，学习率 1e-5 ~ 2e-4
- 技巧：可用 LoRA 节省显存，混合不同任务类型

### 阶段 2：偏好对齐
- **方案 A（简单路线）**：离线 DPO，使用现有偏好数据集
- **方案 B（中等路线）**：在线 DPO/拒绝采样，用 SFT 模型生成 + 奖励模型打分
- **方案 C（完整路线）**：RLHF/PPO，训练独立奖励模型 + 在线 RL 优化

### 阶段 3（可选）：推理能力增强
- 使用 GRPO + RLVR 在数学/编程任务上进一步提升
- 或使用 rejection sampling 构造高质量推理链数据做额外 SFT

### 阶段 4（可选）：安全过滤
- Constitutional AI 原则审查
- 红队测试（Red Teaming）
- 安全分类器部署

## 九、未来展望

1. **RL 从对齐走向能力激发**：DeepSeek-R1 证明 RL 不仅能对齐模型，还能激发新能力。预计 2026 年会有更多模型采用 RLVR 范式训练推理能力。

2. **合成数据的深化应用**：AI 生成偏好数据（RLAIF）和合成 SFT 数据的质量正在快速提升，有望进一步降低人工标注的需求。

3. **多目标对齐**：如何在有用性、安全性、诚实性之间取得动态平衡，仍然是开放的研究问题。

4. **个性化对齐**：不同用户对"好回答"的定义不同，如何实现个性化的偏好对齐是重要方向。

5. **方法融合**：ORPO 和 SimPO 等方法展示了将 SFT 与对齐合并的可能性，未来可能出现更多端到端的一步式训练方法。

6. **可验证奖励的扩展**：RLVR 目前主要适用于有明确答案的任务，如何扩展到更主观的任务（创意写作、对话等）是关键挑战。
