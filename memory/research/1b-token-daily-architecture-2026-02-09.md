### 2.2 任务队列设计

```python
# 优先级定义
class Priority(Enum):
    CRITICAL = 0   # 用户直接请求，实时需要
    HIGH = 1       # 时效性任务（新闻分析、漏洞检测）
    MEDIUM = 2     # 常规批处理（代码分析、文档生成）
    LOW = 3        # 后台填充（知识图谱、数据清洗）
    IDLE = 4       # 闲时任务（创意生成、模拟对话）

# 任务结构
@dataclass
class Task:
    id: str
    priority: Priority
    complexity: float          # 0.0-1.0，决定模型路由
    input_tokens_est: int      # 预估输入 token
    output_tokens_est: int     # 预估输出 token
    max_retries: int = 3
    timeout_seconds: int = 300
    model_preference: str = None  # 可选指定模型
    batch_eligible: bool = True   # 是否可以走 Batch API
    created_at: datetime
    deadline: datetime = None     # 截止时间
```

#### 队列策略
- **实时队列** (5%)：直接调用 API，走标准定价
- **准实时队列** (15%)：小批量聚合（1-5分钟窗口），走 Flex 定价
- **批处理队列** (80%)：大批量聚合（1-24小时窗口），走 Batch API（50%折扣）

### 2.3 Agent 分层架构

#### Planner（规划者）
- **使用模型：** Claude Sonnet 4.5 / GPT-5
- **Token 消耗：** ~5% (50M/day)
- **职责：** 接收高级任务，拆解为子任务，分配优先级和复杂度标签
- **特点：** 需要强推理能力，但调用次数少

#### Worker（执行者）
- **使用模型：** 根据复杂度路由（nano → mini → standard → premium）
- **Token 消耗：** ~85% (850M/day)
- **职责：** 执行具体任务（代码生成、文本分析、数据处理等）
- **特点：** 高吞吐，大量并行

#### Reviewer（验证者）
- **使用模型：** Claude Haiku 4.5 / GPT-4.1-mini（轻量验证）
- **Token 消耗：** ~10% (100M/day)
- **职责：** 质量检查、一致性验证、结果评分
- **特点：** 快速判断，低成本

### 2.4 智能模型路由

```python
def route_model(task: Task) -> str:
    """根据任务复杂度和预算选择最优模型"""
    
    if task.complexity < 0.2:
        # 简单任务：分类、提取、格式化
        if task.batch_eligible:
            return "gpt-5-nano-batch"  # $0.025/$0.20 per M
        return "gemini-flash-lite"      # $0.10/$0.40 per M
    
    elif task.complexity < 0.5:
        # 中等任务：摘要、翻译、简单分析
        if task.batch_eligible:
            return "gpt-5-mini-batch"  # $0.125/$1.00 per M
        return "deepseek-v3.2"          # $0.28/$0.42 per M
    
    elif task.complexity < 0.8:
        # 复杂任务：代码生成、深度分析
        return "claude-sonnet-4.5"      # $3.00/$15.00 per M
    
    else:
        # 最高难度：架构设计、科研推理
        return "claude-opus-4.5"        # $5.00/$25.00 per M
```

### 2.5 并行与调度策略

#### 并行度计算

1B tokens/day = 11,574 tok/s

假设平均请求：2,000 输入 + 500 输出 = 2,500 tok/请求
- 每天请求数：1B / 2,500 = **400,000 requests/day**
- 每秒请求数：~**4.6 requests/second**
- 假设平均响应时间 10s → 并发数 = **~46 个并行请求**

但如果使用 Batch API（80% 流量）：
- 实时并发：仅需 ~10 个并行请求
- Batch 提交：每小时打包 ~13,333 个请求提交

#### 速率限制管理

| API | RPM 限制 (Tier 4+) | TPM 限制 | 占用比 |
|-----|-------|---------|--------|
| Claude (Scale tier) | 4,000 | 400K | ~1.7 RPM 实际 |
| OpenAI (Tier 5) | 10,000 | 30M | 很充裕 |
| Gemini (Pay-as-you-go) | 2,000 | 4M | 需要多项目 |
| DeepSeek | 无硬限制 | 无硬限制 | 但可能被限速 |

**策略：** 多 API key / 多账号 + 负载均衡，确保不触顶

### 2.6 错误处理与韧性

```python
# 降级链
FALLBACK_CHAIN = {
    "claude-opus-4.5": ["gpt-5", "claude-sonnet-4.5", "gemini-3-pro"],
    "claude-sonnet-4.5": ["gpt-4.1", "gemini-2.5-pro", "deepseek-v3.2"],
    "gpt-5-nano-batch": ["gemini-flash-lite-batch", "deepseek-v3.2"],
}

# 熔断器配置
CIRCUIT_BREAKER = {
    "failure_threshold": 5,        # 连续 5 次失败触发
    "recovery_timeout": 60,         # 60 秒后半开
    "half_open_max_requests": 3,    # 半开状态最多 3 个探测请求
}
```

#### 重试策略
- 429 (Rate Limited): 指数退避 + 切换到备用模型
- 500 (Server Error): 最多重试 3 次，间隔 1s → 5s → 15s
- 超时: 降级到更快的模型
- 成本超限: 暂停非关键任务，仅保留 CRITICAL

- **成本：** ~$5-10/天
- **工作：**
  - 多模型路由（2-3 个 API）
  - Batch API 集成
  - 自动化任务发现（GitHub API, arXiv RSS）
  - 结果存储和索引（PostgreSQL + 向量数据库）

### Phase 2: 百倍扩展（第 5-8 周）
- **目标：** 100M tokens/day
- **成本：** ~$50-100/天
- **工作：**
  - 完整的 5 个 API 提供商集成
  - Agent 分层架构（Planner/Worker/Reviewer）
  - 熔断器和降级机制
  - 成本实时监控和预警
  - 任务优先级动态调整

### Phase 3: 达成目标（第 9-12 周）
- **目标：** 1B tokens/day
- **成本：** ~$500-600/天
- **工作：**
  - 10x 并发扩展
  - 全量任务流水线上线
  - 缓存优化（prompt caching 利用率 >50%）
  - 自托管开源模型节点上线（可选）
  - 成本优化迭代

### Phase 4: 稳态运营（持续）
- **目标：** 稳定 1B+/day
- **工作：**
  - A/B 测试不同模型效果
  - 任务质量自动评估
  - 新模型自动纳入路由池
  - 成本持续优化
  - 知识库持续膨胀和利用

## 七、风险与缓解

| 风险 | 影响 | 缓解 |
|------|------|------|
| API 价格上涨 | 成本超预算 | 多供应商冗余 + 自托管兜底 |
| 速率限制收紧 | 吞吐量下降 | 多账号 + Batch API + 自托管 |
| 免费层取消 | 零成本部分消失 | 预算中已不依赖免费层 |
| 模型质量下降 | 任务质量下降 | Reviewer 自动检测 + 切换模型 |
| 服务宕机 | 任务中断 | 多供应商 failover + 队列持久化 |
| token 浪费 | 成本效率低 | 定期审计任务有效性和输出质量 |

## 八、结论

构建每天消耗 1B token 的 AI 系统在 2026 年完全可行，核心发现：

1. **成本已经很低：** 纯粹最低价路线仅需 ~$78/天（GPT-5-nano Batch），推荐混合策略约 $545/天
2. **Batch API 是关键：** 50% 的折扣对大规模消耗至关重要，80% 的任务可以异步处理
3. **智能路由必不可少：** 60% 的 token 可以用最便宜的模型处理，仅 5% 需要旗舰模型
4. **DeepSeek 是性价比冠军：** $0.28/$0.42 的定价在中等复杂度任务上无可匹敌
5. **需求不是瓶颈：** 代码分析、论文处理、数据清洗等任务源几乎无限
6. **3个月可达成目标：** 从 0 到 1B/day 的路径清晰，分 4 个阶段渐进

**建议立即开始 Phase 0，$1/天的成本即可验证核心架构。**
