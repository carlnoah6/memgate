## 未解决 Bug: Run Viewer 详情页空白 → 已修复
- 根因: nginx `alias` + `try_files` SPA fallback 把 `/balatro/game/xxx` 重定向到 `location /`（OpenClaw gateway）
- 第二层问题: `app.js` 用相对路径 `src="app.js"`，从 `/balatro/game/xxx` 加载变成 `/balatro/game/app.js` → 返回 HTML → `Unexpected token '<'`
- 修复: 彻底放弃 SPA，改为 FastAPI 服务端渲染
  - `@app.get("/game/{run_code}")` → 服务端拼 HTML，包含所有截图和样式
  - `@app.get("/")` → 服务端渲染列表页
  - nginx `/balatro/game/` 和 `/balatro/` 都 proxy_pass 到 FastAPI
  - 不再需要 `app.js` 做路由
- 教训: **nginx alias + try_files 的 fallback 路径是内部重定向，会匹配到其他 location block**

### 关键教训（本次固化）

**1. Planner 依赖分析必须逐步检查 input/output**
- 不能凭直觉说"可以并行"，每步问"输入从哪来"
- 从零建 repo 的任务基本都是串行的

**2. replan vs cancel+init 的适用场景**
- plan 已 active → 用 replan（保留已完成步骤）
- plan 还在 draft → cancel+init 可以（没有已完成步骤要保留）
- replan 会跳过 draft 确认流程，直接变 active

**3. Modal Volume 必须 reload()**
- 每个 Modal function 是独立容器
- 前一步 commit() 的数据，后一步必须 reload() 才能看到
- 已修复: 所有函数开头加了 training_vol.reload()

**4. 超时统一管理**
- planner_helpers.py: DEFAULT_STEP_TIMEOUT_MIN = 15
- normalize_step() 支持 timeout_min 字段
- planner_spawn.py 从 step 读取 timeout_min 传给 agent/bridge
- planner.py 硬超时 = max(timeout_min * 1.5, 45)
- DB plan_steps 表新增 timeout_min 列

**5. 大任务先试跑再估算**
- 先用最小数据跑一次，记录实际耗时
- 根据实际耗时估算完整数据的耗时和资源
- 设置合理超时（实际耗时 × 2）
- 不凭感觉猜超时
